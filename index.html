What the review shows you

Three things from that sample that a line-by-line diff of the file would not tell you.

  1. A prefix rule that catches more than intended

    Rules match from the start of the path, so Disallow: /search also blocks /searchlight-collection, a product category, for every search engine.

  2. A cleanup that quietly opens pages

    Dropping Disallow: /*?sort= makes sorted collection URLs crawlable again. The cell turns green and names the rule that used to block it.

  3. Search stays open while training closes

    GPTBot and ClaudeBot lose everything, while OAI-SearchBot and PerplexityBot keep the same access, because a named group replaces the * group only for the crawlers it names.

How it works

The matcher follows RFC 9309, the robots.txt standard, and Google's documented reading of it.

Paste both versions
The file live today and your edit. Leave the current file empty if the site has none. Each file is linted as you type: misspelled fields, rules outside a group, paths without a leading slash, sitemap lines that are not full URLs.
List the paths that matter
Paste paths or full URLs, one per line: top landing pages, a sample from your sitemap, anything a stakeholder asked about. Pick crawlers by purpose: search, AI training, AI search, user-triggered AI, or add your own token.
Review the changed cells
Each cell compares before and after. Select one to see which group applied and which line decided it in each file. The longest matching rule wins; when an Allow and a Disallow are equally long, Allow wins.
Export for the pull request
Copy a Markdown summary of every change for the PR description, or download the full matrix as CSV.

Privacy and limits

  • Local only. Parsing and matching run in this page. The production build ships a Content-Security-Policy that forbids network requests, so pasted files cannot leave your browser.
  • Paste, don't fetch. Browsers cannot read another site's robots.txt directly, so the tool asks you to paste it. Open /robots.txt on your site and copy it.
  • A request, not a lock. robots.txt asks crawlers to stay out. It does not stop a crawler that ignores it, and it does not remove pages that are already indexed.
  • Your paths only. The review covers the paths you list. A path you leave out is not checked.
  • Interpretation. Verdicts follow RFC 9309 and Google's rules. Some crawlers parse differently, and firewall or CDN bot rules are invisible to robots.txt.

Questions

Which crawlers are included?

Googlebot, Googlebot-Image, Bingbot, DuckDuckBot, Applebot, Google-Extended, Applebot-Extended, GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-SearchBot, Claude-User, PerplexityBot, Perplexity-User, CCBot, Bytespider, Meta-ExternalAgent and Amazonbot, each linked to its operator's documentation where one exists. You can add any other product token.

Why does Googlebot-Image follow my Googlebot rules?

Google's crawlers use the most specific group that names them. Googlebot-Image looks for its own group first, then the Googlebot group, then *.

Does blocking Google-Extended remove me from Google Search?

No. Google-Extended is a control token, not a crawler. Google documents that it does not affect inclusion or ranking in Google Search.

Will user-triggered AI agents respect these rules?

Not reliably. OpenAI says robots.txt rules may not apply to ChatGPT-User, and Perplexity says Perplexity-User generally ignores them. The matrix shows what the file asks, and the inspector notes these cases.

What can I export?

A Markdown change summary for a pull request, and a CSV with one row per path and crawler: both verdicts, the deciding lines and the change type.
